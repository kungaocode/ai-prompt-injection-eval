Qwen3-4B-Base 领域继续预训练实验流程说明
==============================================

一、实验背景与目标
------------------

本次实验的目标是：在消费级显卡（NVIDIA RTX 4060 8 GB）上，使用 QLoRA 技术
对 Qwen3-4B-Base 基础模型进行领域继续预训练（Continued Pretraining），使其
掌握计算机科学、密码学与信息安全三个领域的专业知识和术语。训练结束后，模型应
能更好地理解和生成这些领域的文本。

五、微调方案设计
----------------

5.1 方案选择：QLoRA
  面临的核心约束：RTX 4060 只有 8 GB 显存，而 Qwen3-4B 全参数加载需要约 8 GB
  （FP16），加上优化器状态和激活值，全参数微调需要 30+ GB 显存，完全不可行。

  因此选择 QLoRA（Quantized Low-Rank Adaptation）方案，组合了三种技术：
    - 4-bit 量化：将模型权重从 FP16 压缩到 4-bit，显存降低约 4 倍
    - LoRA：只训练低秩适配器矩阵，不修改原始权重，可训练参数仅占总参数的
      0.81%，大幅降低优化器显存和训练开销
    - 梯度检查点：在反向传播时重新计算激活值，以少量计算换取显存节省

5.2 LoRA 参数设计
  经过分析 Qwen3 的架构后，决定在所有线性投影层上应用 LoRA：
    - Self-Attention 层: q_proj, k_proj, v_proj, o_proj（4 个投影矩阵）
    - FFN 层: gate_proj, up_proj, down_proj（3 个投影矩阵，对应 SwiGLU 结构）
  共计每层 7 个目标模块，36 层共 252 个 LoRA 适配器。

  超参数选择：
    - r = 16: 平衡适配器容量和参数量。太低（如 8）可能不足，太高（如 64）
      会浪费显存
    - alpha = 32: 缩放因子 alpha/r = 2，给 LoRA 权重合理的信号强度
    - dropout = 0.05: 轻度过拟合防护，5% 是常用值
    - bias = "none": 只训练低秩矩阵，不训练 bias，进一步减少参数量

5.3 量化方案设计
  - 使用 NF4 (NormalFloat4) 数据类型：QLoRA 论文提出的信息论最优 4-bit
    量化格式，假设权重服从正态分布
  - 启用双重量化：对量化常数再次进行 8-bit 量化，每参数额外节省 ~0.4 字节
  - 计算精度使用 FP16：反量化后以 FP16 进行计算，确保前向/反向传播精度

5.4 训练超参数设计
  - Batch size = 1: 受显存限制，单次只能处理 1 条样本
  - 梯度累积 = 8: 等效 batch size = 8，弥补单条样本训练的不稳定性
  - 学习率 = 2e-4: QLoRA 论文推荐的 LoRA 训练学习率
  - Warmup = 50 步: 训练初期稳定训练，防止早期梯度震荡
  - Epochs = 3: ~10M tokens 的数据量，3 轮训练充分且不会严重过拟合
  - Cosine 学习率调度: 末期平滑衰减到接近 0，有利于收敛到更好的局部最优
  - 序列长度 = 2048: 在上下文覆盖和显存之间取得平衡
  - 优化器 = AdamW: 权重衰减与学习率解耦，当前主流选择
  - 数据加载进程 = 0: Windows 下多进程数据加载可能导致死锁，设为 0 避免


六、代码实现详解
----------------

6.1 整体架构
  代码文件为 train_qwen3_4b.py，采用模块化结构：
    - 配置区: 路径、训练参数、LoRA 参数集中定义
    - load_and_prepare_dataset(): 数据加载与预处理函数
    - main(): 主训练流程

6.2 Windows 兼容性处理
  由于在 Windows 下运行，需要处理多进程问题：
    - freeze_support(): 打包成 exe 时的必需调用
    - set_start_method("spawn"): Windows 不支持 fork，必须使用 spawn 模式
    - dataloader_num_workers = 0: 避免子进程递归创建问题
    - 模块入口保护: if __name__ == "__main__" 确保子进程不会重新执行主代码

6.3 数据加载实现
  load_and_prepare_dataset 函数的处理流程：
    1. 使用 os.walk 递归遍历 DATASET_DIR 下所有目录
    2. 筛选 .jsonl 文件，逐行读取并解析 JSON
    3. 提取 "text" 字段，过滤空文本和短于 50 字符的文本
    4. 将清洗后的文本转换为 HuggingFace Dataset 对象
    5. 使用 tokenizer 批量分词，截断到 max_length=2048
    6. 移除原始 text 列，仅保留 input_ids 和 attention_mask
    7. 按 90:10 比例随机划分训练集和验证集（seed=42）

6.4 模型加载实现
  模型加载流程：
    1. 配置 BitsAndBytesConfig，指定 4-bit 量化参数
    2. 使用 AutoModelForCausalLM.from_pretrained 加载模型，传入量化配置
    3. device_map="auto" 自动分配到 GPU VRAM
    4. attn_implementation="sdpa" 启用优化的注意力计算
    5. prepare_model_for_kbit_training 调整模型结构以支持量化训练
    6. 启用 gradient_checkpointing 用计算换显存

6.5 LoRA 注入实现
  使用 PEFT 库的 LoraConfig 和 get_peft_model：
    1. 创建 LoraConfig，指定 r/alpha/dropout/target_modules/task_type
    2. 调用 get_peft_model 将 LoRA 适配器注入基础模型
    3. 打印可训练参数统计，验证参数量在预期范围内
    结果：可训练参数 33,030,144，占总参数 4,055,498,240 的 0.8145%

6.6 训练器配置
  使用 TRL 的 SFTTrainer 和 SFTConfig：
    - SFTConfig 配置所有训练参数（批次、学习率、保存策略等）
    - SFTTrainer 封装模型、数据集和分词器
    - dataset_text_field="text" 指定数据字段
    - packing=False 每条样本独立处理
    - 语法上已适配 TRL >= 1.8 版本（使用 processing_class 参数）

6.7 模型保存
  训练结束后分两步保存：
    1. 保存 LoRA 适配器: 仅保存训练的低秩矩阵权重，文件小，灵活性高
    2. 合并并保存完整模型: 调用 merge_and_unload() 将 LoRA 权重融入基础模型
       权重中，生成可直接用于推理的完整 safetensors 格式模型

八、关键设计决策总结
--------------------

  决策 1：选择 QLoRA 而非全参数微调
    理由：8 GB 显存下全参数微调完全不可行。QLoRA 通过 4-bit 量化将模型
    压缩到 ~2 GB，LoRA 只训练 0.81% 的参数，使得训练成为可能。

  决策 2：选择继续预训练而非指令微调
    理由：目的是让模型学习领域知识，而非学会对话格式。使用纯文本格式
    {"text": "..."}，不包含任何指令模板或对话结构。训练后的模型仍然是
    Base 模型，可以后续再做指令微调。

  决策 3：LoRA 覆盖全部线性层
    理由：对 Self-Attention 的全部投影矩阵（Q/K/V/O）和 FFN 的全部线性层
    （gate/up/down）都应用 LoRA，实现全方位的领域适应。虽然增加了少量参数，
    但适配效果更好。

  决策 4：不使用混合精度（fp16=False, bf16=False）
    理由：基础模型已经是 4-bit 量化并且计算精度设为 FP16，再启用混合精度
    会造成冲突。模型的前向/反向传播本身就以 FP16 精度计算。

  决策 5：不启用序列打包（packing=False）
    理由：领域文本是不连续的独立文档，打包会将不同文档拼接在一起，跨文档
    边界的 token 预测没有意义，会影响训练质量。

  决策 6：使用 SDPA 注意力实现
    理由：PyTorch 原生 SDPA 会根据输入自动选择最优实现（Flash Attention 2
    或 Memory-Efficient Attention），吞吐量更高、显存占用更少。

十、后续可能的改进方向
----------------------

  1. 增加训练数据量和领域覆盖面
  2. 尝试更长的序列长度（如 4096），利用更好的上下文信息
  3. 使用更大的 rank（如 r=32 或 r=64），增加适配器容量

  6. 使用 wandb 等工具可视化训练曲线，便于调试和监控
  7. 在领域下游任务（如分类、问答）上评估微调效果
